NEW CHANGES - MONGODB IMPLEMENTATION
==================================================

1. FILES CHANGED

- File: server/adhoc/src/main/java/com/helicalinsight/adhoc/services/MongoDrillLoader.java
  - Added a missing return statement in the MongoModel.testConnection() method.
    In the no-authentication branch (when username, password, or authMechanism
    is null), the method was creating a MongoClient and getting the database
    but never returning true. It was silently falling through to return false
    at the bottom of the method. One line was added:
      return this.mongoDb != null;

- File: server/hi-repository/System/Admin/Static/DataSourcesList.groovy
  - Moved the MongoDB driver entry and the staticMongoArray addition outside
    the Apache Drill enabled gate (if drillEnabledTypes block).
    Previously, MongoDB only appeared as an available datasource in the UI
    when Apache Drill was enabled. MongoDB connectivity via the native
    mongo-java-driver is independent of Drill. The change ensures MongoDB
    is always listed as a connectable datasource regardless of whether
    Apache Drill is configured or enabled.


2. PURPOSE OF EACH CHANGE

- MongoDrillLoader.java: The testConnection() method always returned false
  when no username/password/authMechanism was provided, even if the MongoDB
  server was reachable. This made all unauthenticated MongoDB connection tests
  fail incorrectly. The fix adds the missing return statement so the test
  correctly reports success or failure.

- DataSourcesList.groovy: MongoDB was hidden from the datasource selection
  screen unless Apache Drill was enabled. Since MongoDB uses its own native
  driver (mongo-java-driver 3.12.10) and does not depend on Drill to connect,
  it should always be available. The fix decouples MongoDB availability from
  the Drill enabled flag.


3. MONGODB CONNECTION FLOW

- User opens the datasource configuration screen in Helical Insight.
- MongoDB appears in the "No SQL & Big Data" category (always, regardless
  of Drill status) with driver identifier: com.helicalinsight.nosql.mongo
- User fills in: host, port, database, and optionally username, password,
  and authentication mechanism.
- User clicks "Test Connection".
- GlobalConnectionsTester checks that dataSourceProvider == "noSql" and
  calls DataSourceUtils.testNosqlDS().
- DataSourceUtils.testNosqlDS() reads the driver name (subType) from the
  form data and calls NoSqlUtils.getNoSqlImplementation("com.helicalinsight.nosql.mongo").
- Spring returns the MongoDrillLoader bean (annotated @Component with that name).
- MongoDrillLoader.testConnection() builds a MongoModel from the form fields
  (host, port, jdbcUrl, database, username, password, authMechanism).
- MongoModel.testConnection() connects using mongo-java-driver 3.12.10:
    - No credentials: new MongoClient(host) -> getDB(database) -> returns db != null
    - With credentials: builds MongoCredential, optionally uses MongoClientURI,
      calls getDB(database) and getAddress() -> returns db != null
- Result is returned to the user as a success or failure message.
- On success, the datasource is saved and available for report building.
